# S3

> One section of Twig's hard-won lessons. The index, the ship checklist and the
> shared conventions are in [CLAUDE.md](../../CLAUDE.md); the other sections live
> beside this file in [docs/lessons/](.).

**(★ 2026-08-16, `S3FileSystem`/`Sigv4`)** Zero new dependencies — HTTP uses the existing
OkHttp, XML uses WebDAV's `DocumentBuilderFactory`, and SigV4 is hand-written on the JDK's
HMAC-SHA256. **Never bring in the AWS SDK for Java**: the s3 module alone pulls in over ten MB
of dependencies, more than the whole APK, while all we use is a handful of REST calls. Pitfalls
and settled decisions:

- **★ The request path and the object names in responses are two different encoding spaces;
  do not treat them as one** (found by pointing it at a real MinIO on 2026-08-16, while the
  mock tests stayed green throughout):
  - **Request path / canonical URI = RFC 3986** (unreserved set `A-Za-z0-9-_.~`).
    You cannot use `URLEncoder`: it encodes a space as `+`, encodes `~` as well, and does not
    encode `*`. See `Sigv4.uriEncode`.
  - **The Key/Prefix/Delimiter inside an `encoding-type=url` response is form encoding**
    (`application/x-www-form-urlencoded`). Measured on the raw wire:
    `my notes.txt → my+notes.txt` (a space is `+`, **not** `%20`),
    `a+b.txt → a%2Bb.txt` (a literal plus is escaped, so `+` is unambiguous),
    `100% done #1.txt → 100%25+done+%231.txt`. Decoding therefore has to replace `+` with a
    space **first** and decode `%XX` **second**; the other way round, the plus decoded from
    `%2B` becomes a space and `a+b.txt` turns into `a b.txt` — **the listing looks fine and
    clicking gives a 404**. See `S3FileSystem.decodeKey`.
  - **`NextContinuationToken` is unaffected by `encoding-type`** and is an opaque value
    (measured: the `=` inside comes back verbatim). Running it through the object-name form
    decoding would turn the `+` in base64 into a space and break pagination instantly — do not
    decode it at all, pass it back to the server exactly as received (uriEncoded normally when
    sending).
  - Lesson: **only a real server can catch this**. Mock tests assert our own imagination about
    the wire and stay green even with the encoding direction reversed; `S3LiveTest` (against a
    real MinIO) caught it on the first run.
- **The string being signed must match the bytes actually sent, exactly.** URLs are encoded by
  us end to end via `encodedPath`/`encodedQuery` so okhttp does not re-encode by its own rules,
  and the canonical query and the real query share the same output from `Sigv4.canonicalQuery`.
  One character off means SignatureDoesNotMatch, and the server will not tell you where — which
  is why `Sigv4Test` **asserts on the intermediate products** (the canonical request and the
  string to sign). Matching the canonical request SHA-256 printed in the official documentation
  proves that the first half of the normalization is byte-perfect.
- **S3 has no directories**; directories in the tree come from two things: `delimiter=/` makes
  the server fold them into `CommonPrefixes`, and empty objects whose key ends in `/` act as
  placeholders (otherwise **an empty directory with no objects simply does not exist** and
  disappears after creating and refreshing). Those placeholders must be filtered out when
  listing, or 0-byte phantom files appear.
- **Uploads use multipart and never touch disk** (WebDAV's "write to a temp file then PUT the
  whole thing" needs an equally large amount of storage for a big file). Anything smaller than
  one part (8 MiB) still uses a single PUT, saving the initiate/complete round trips. On failure
  you **must** `AbortMultipartUpload` — otherwise the parts sit in the bucket accruing storage
  charges and are **invisible** in the console's object list. Part payload hashes use
  `UNSIGNED-PAYLOAD`: re-reading 8 MiB to compute SHA-256 for the signature burns CPU for
  nothing, and S3 accepts that value.
- **Moves/renames within the same endpoint use the server-side `CopyObject`**
  (`moveWithin` + `rename`), so even a multi-GB object is one request; without overriding
  `moveWithin`, `CopyEngine` would dutifully download and re-upload it.
- **CopyObject and CompleteMultipartUpload return 200 first and then stream the result**, with
  failures hidden in an `<Error>` element in the body rather than in the status code. Checking
  only `isSuccessful` turns a failure into a success.
- **In path style, bucket-level operations are `/bucket` with no trailing slash** (with one,
  some compatible implementations treat it as "an object with an empty name"). In virtual-host
  style the bucket goes into the hostname and never appears in the path.
- **The bucket name may be left empty**: then the root lists all buckets in the account. But
  many credentials are only authorized for a single bucket and lack `ListAllMyBuckets`, in which
  case a bucket name is required or you get an AccessDenied immediately. Conversely, when a
  bucket name is given **the root is that bucket and deleting it is not allowed** — deleting it
  empties the entire connection, while all the user sees is the row they pressed delete on.
- `openRandom` is an HTTP Range request and `randomAccessEfficient() == true`, so network video
  thumbnails and player seeking benefit; that stream-pool logic is shared with WebDAV as
  `HttpRangeSource`.
- **Two test layers, both required**: `S3FileSystemTest` (mockwebserver, wire level) pins the
  bytes we send; `S3LiveTest` (against a real server, **skipped entirely if the environment
  variables are unset**, so `./gradlew test` stays green) pins that the server accepts them. The
  encoding pitfall above was caught by the latter — the former can prove neither that the
  signature is accepted nor that our understanding of the response format is right. A local
  MinIO is enough:
  ```
  docker run -p 9000:9000 -e MINIO_ROOT_USER=<key> -e MINIO_ROOT_PASSWORD=<secret> \
    minio/minio server /data          # then create a bucket
  TWIG_S3_ENDPOINT=http://127.0.0.1:9000 TWIG_S3_KEY=<key> \
  TWIG_S3_SECRET=<secret> TWIG_S3_BUCKET=<bucket> \
    ./gradlew :fs-network:test --tests "*S3LiveTest*"
  ```
